OPTIMIZATION OBJECTIVEThree Cross Entropy losses, one update

For each task t, class weights use only that fit's training subset. For present class c, w(t,c)=Ntrain/(Kpresent × count(t,c)); absent classes receive zero weight. PyTorch's weighted-mean CrossEntropyLoss divides weighted negative log likelihood by the sum of target-class weights in the batch.

Ljoint = (α1 Lissue + α2 Ldomain + α3 Lentity) / (α1 + α2 + α3)

The α values are fixed hyperparameters for a fit, either 1:1:1 or 1:2:2. They are not class weights and are not learned uncertainty weights. One backward pass accumulates gradients in shared/tail parameters and all task heads. Serving computes probabilities and XAI gradients only; it performs no optimizer update.

Historical tail training uses AdamW weight_decay=0.01, batch32, seed42, head LR0.0003. Below are the actual saved checkpoint configurations, read directly from fold*.pt; the module default is not assumed to describe every fold.

SOURCE 10

Class weighting, joint CE and gradient update

Each task uses CrossEntropyLoss with training-subset class weights. Aggregate fixed task weights, divide by their sum, backpropagate one scalar through all heads/shared/tail. CUDA AMP scales gradients, unscales, clips norm to 1, steps AdamW and updates the scaler. The optimizer has separate tail and head learning rates.

REPRODUCIBILITY & DELIVERYVerification notes

Checkpoint identity: e42-tail-grid-v1. All nine release asset hashes and dataset SHA are validated before model loading. Five outer-fold splits cover 740 unique IDs; strict state loading rejects incompatible parameters.

Local launcher changes: Linux uses ${TEMPO_BACKEND:-e42-tail-grid}; Gunicorn uses os.environ.setdefault('TEMPO_BACKEND', 'e42-tail-grid'). Windows retains its conditional E42 default. Overrides are intentional and unknown backends raise visibly. E42 startup logs backend and version. Gunicorn remains one worker/four threads, without a second preflight model instance. Linux preflight exits before the application initializes.

XAI scope: Visual attribution is class-specific absolute gradient × activation with text held fixed. LIME/occlusion perturb headline, not supporting text. E42's inherited LIME callback uses the E42 tails and heads. Historical revision evidence describing attention rollout or baseline B/32 should not be used to label the current web algorithm. Heatmaps are model sensitivity, not causal proof.

Input-length limitation: The audited cache/training uses 128 tokens, whereas inherited serving preprocessing uses 256 for edited/new text and text perturbations. This existing difference is preserved and documented; ensemble uploads and edited inputs are not claimed to reproduce a new benchmark. Softmax scores are uncalibrated.

Runtime evidence: See executed commands and observed results, Linux/Gunicorn preparation, and HTTP evidence artifacts. Startup validates checkpoint/cache assets; backbones are lazy-loaded and their pinned files are hash-checked when needed. Prepare backbone caches before enabling offline production traffic. Native Windows and a VPS deployment are separate verification scopes.

Related historical architecture audit: R18 architecture and Joint Loss. Current web behavior above is established by source tracing and runtime evidence, rather than historical prose.
